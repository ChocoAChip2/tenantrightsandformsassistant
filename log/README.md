- `2026-09-07-sidebar-menu-reorg-and-ux.txt` — Fixed the Settings/Log-out popup rendering permanently open (a `[hidden]`-vs-`display` CSS cascade bug, also fixed identically in reset_password.html) and, once fixed, made it structurally impossible for the popup to cover the conversation list or an open Archived folder (column-reverse in-flow layout instead of a floating overlay); moved per-row Archive/Delete/Restore behind a "..." menu; added client-side spam-prevention for "+ New chat"; folder emoji on the Archived section; Enter-to-send/Shift+Enter-for-newline in the message box.
- `2026-09-07-strip-frontend-comments.txt` — Removed all 231 HTML/CSS/JS comments from the six templates, which were being served verbatim to anyone opening View Source (the frontend is entirely inline, with no build step). The rationale moved to `docs/frontend/` — including `css-gotchas.md`, the load-bearing rules that look removable and aren't. Stripped with a purpose-built string-aware scanner (unit-tested against URLs-in-strings, regex literals and Jinja tags first) and verified with `node --check` on every rendered script block plus a Playwright pass with zero console errors; a new test fails if a comment ever reaches a page again. Also dropped the "New chat name (optional)" input — conversations are named "New conversation" and renamed afterward via the "..." menu or double-click.
- `2026-09-07-encryption-pdf-and-markdown.txt` — Encryption at rest for message bodies and conversation titles (AES-256-GCM) with a versioned envelope so the cipher and the key can both be changed later, and stale rows re-encrypting themselves as they are read; the threat model stated plainly in `docs/data-encryption.md` (it is not end-to-end, and cannot be while Gemini reads the conversation). Plus three real bugs found by rechecking: the chat auto-scroll was a no-op because it scrolled `#chat-box` instead of `main`; the RA-81 PDF was producing blank forms (no /AcroForm cloned, a field name that doesn't exist, page 2 never filled, and a shared /tmp path two tenants could race on); and assistant replies showed literal `**` instead of formatting. Also caught and fixed an XSS in the new Markdown renderer before it shipped.
- `2026-09-07-account-deletion-and-message-cap.txt` — Account deletion from Settings with a double confirmation (type your email + tick an acknowledgement, both re-checked server-side) and a 30-day cancellable grace period, with the actual purge running as a `SECURITY DEFINER` pg_cron job in Postgres rather than in the web app (which has no service-role key by design); the first SQL checked into this repo, under `supabase/migrations/`. Also lowered the per-message cap from 8000 to 4000 characters and made it visible with a live "N characters left" counter that appears with 250 to go; rewrote the AI system prompt so replies answer the question actually asked and vary in shape instead of always running the intake script (the PDF-intake JSON contract is unchanged); and added a small `prefers-reduced-motion`-aware motion pass.
- `2026-09-07-rate-limiting-csrf-and-rename.txt` — Added CSRF protection (Flask-WTF), rate limiting (Flask-Limiter) with per-route limits plus a blanket default, an exponentially-escalating login lockout after 10 failed attempts, a 2MB request-size cap, a per-message length cap, session-cookie hardening, standard security headers, and a POST-only (CSRF-protected) logout; implemented the previously-stubbed empty-conversation sweep; added conversation renaming (a "..." menu item and double-click-to-rename); made homepage suggestion chips auto-send their prompt into the new chat; replaced the emoji password show/hide icons with theme-aware SVGs; redesigned the message composer (auto-growing textarea, circular send button); verified a conversation_id in the URL can't leak another user's conversation; fixed message bubbles overflowing on long unbroken text; made the header title a link back to the chat page; verified the color theme already follows the browser's preference and the homepage greeting already varies by time of day; added a small usability/formality pass (disabled+labeled submit buttons, smoother hover transitions) across the login/signup/password pages.
